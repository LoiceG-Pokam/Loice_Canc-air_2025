Étape 2 : Copier les Fichiers vers C:\

Pourquoi C:\ ? Évite les problèmes réseau avec H:\

mkdir "C:\Users\lpokambo\addok_work"

robocopy "H:\PFE Loice\Notebooks\Loice_Canc-air_2025\loice_pneumodetect\pneumodetect\geocodage\addok_bd" "C:\Users\lpokambo\addok_work" /E /XD venv

⚠️ Remplacez lpokambo par votre utilisateur Windows !

❌
Ne copiez JAMAIS un dossier venv existant ! Sous Windows, un environnement virtuel n'est pas déplaçable : les fichiers Scripts\pip.exe, Scripts\addok.exe, etc. contiennent en dur le chemin absolu d'origine (ex. C:\addok_bd\venv\Scripts\python.exe). Si vous copiez ce dossier ailleurs, ces exécutables continueront à chercher Python à l'ancien emplacement, qui n'existe plus — et tout casse silencieusement, avec des erreurs qui semblent aléatoires (ModuleNotFoundError, Fatal error in launcher, etc.). C'est pour ça que /XD venv exclut ce dossier de la copie ci-dessus : on va le recréer proprement à l'étape suivante.

Si vous n'avez pas robocopy ou préférez rester simple, copiez tout puis supprimez le venv copié :

copy "H:\PFE Loice\Notebooks\Loice_Canc-air_2025\loice_pneumodetect\pneumodetect\geocodage\addok_bd\*" "C:\Users\lpokambo\addok_work\"
Remove-Item -Recurse -Force "C:\Users\lpokambo\addok_work\venv"

🔧 Vous avez déjà un venv copié (cassé) ? Réparez-le maintenant

⚠️
Si vous voyez une erreur du type Fatal error in launcher: Unable to create process using '"C:\ancien\chemin\venv\Scripts\python.exe" ...', votre venv actuel est un venv copié et cassé. Il faut le supprimer et le recréer à l'endroit actuel.
cd "C:\Users\lpokambo\addok_work"

# Sortez du venv cassé
deactivate

# Supprimez-le
Remove-Item -Recurse -Force ".\venv"

# Recréez-le proprement ICI (chemins corrects garantis)
python -m venv venv
.\venv\Scripts\Activate.ps1

# Réinstallez les paquets
.\venv\Scripts\python.exe -m pip install --upgrade pip --trusted-host pypi.org --trusted-host files.pythonhosted.org
.\venv\Scripts\python.exe -m pip install --trusted-host pypi.org --trusted-host files.pythonhosted.org addok pyreadline3 pandas requests

Vérifiez que ça fonctionne :

.\venv\Scripts\python.exe -m pip show addok

Vous devriez voir Name: addok sans erreur.

⚠️
Règle à retenir : à cause des certificats Zscaler, toute commande pip doit inclure --trusted-host pypi.org --trusted-host files.pythonhosted.org — y compris pip install --upgrade pip. Si vous voyez SSL: CERTIFICATE_VERIFY_FAILED, c'est que ces flags manquent sur la commande que vous venez de taper.

Étape 3 : Créer venv et Installer Addok

💡 Si vous avez suivi l'Étape 2 correctement (sans copier venv), cette étape crée un venv neuf et fonctionnel dès le départ — pas de risque de chemins cassés.

cd "C:\Users\lpokambo\addok_work"

ℹ️
Pourquoi pyreadline3 ? Addok essaie d'importer le module readline au démarrage (normalement présent sur Mac/Linux). Ce module n'existe pas du tout sur Windows, et sans compatibilité, addok plante avant même de démarrer (batch comme serve). pyreadline3 fournit cette compatibilité — installez-le systématiquement sur Windows, en même temps qu'addok.

Étape 4 : Indexation avec filter_ndjson.py

Créez index.py :

import gzip
import os
import subprocess
import sys

FILE_PATH = "adresses-addok-france.ndjson.gz"

# Chemin direct vers l'exe addok du venv (pas de "-m", pas de PATH)
ADDOK_EXE = os.path.join(os.path.dirname(sys.executable), "addok.exe")

print("🚀 Indexation avec filter_ndjson.py...")

with gzip.open(FILE_PATH, 'rb') as f_in:
    # Lancer filter_ndjson.py → addok batch
    proc_filter = subprocess.Popen(
        [sys.executable, "filter_ndjson.py"],
        stdin=f_in,
        stdout=subprocess.PIPE,
        bufsize=65536
    )
    
    proc_batch = subprocess.Popen(
        [ADDOK_EXE, "batch"],   # ⭐ appelle directement l'exe du venv, aucune ambiguïté possible
        stdin=proc_filter.stdout,
        bufsize=65536
    )
    
    proc_batch.wait()

# On vérifie vraiment le code de sortie avant d'annoncer un succès
if proc_batch.returncode != 0:
    print(f"❌ Indexation ÉCHOUÉE (code {proc_batch.returncode}). Regardez le message d'erreur ci-dessus.")
    sys.exit(proc_batch.returncode)

print("✅ Indexation terminée !")

Puis lancez :

python index.py
⚠️
Pourquoi pas python -m addok ? Le paquet addok n'a pas de fichier __main__.py, donc -m addok échoue toujours avec 'addok' is a package and cannot be directly executed — quel que soit l'environnement, même quand addok est correctement installé. Il faut appeler l'exécutable addok.exe généré dans venv\Scripts\, pas le module Python.

⚠️ Erreur fréquente : addok "introuvable" ou "not found"

❌
Si votre prompt affiche (venv) (base) PS ..., deux environnements Python sont actifs en même temps (votre venv ET l'environnement base d'Anaconda). Selon l'ordre du PATH, la commande addok tapée seule peut alors se résoudre vers l'exécutable d'Anaconda au lieu de celui de votre venv — même si venv est bien activé.

🔍 Pour confirmer le conflit :

Get-Command addok -All

Si plusieurs lignes apparaissent, c'est confirmé : il existe plusieurs addok.exe visibles depuis ce terminal.

✅ Solution définitive : appelez toujours l'exécutable du venv par son chemin complet

# Au lieu de :
addok batch
addok serve

# Utilisez toujours :
.\venv\Scripts\addok.exe batch
.\venv\Scripts\addok.exe serve

Cette méthode fonctionne toujours, peu importe le PATH ou les conflits avec Anaconda, car elle ne fait aucune recherche dans PATH : elle exécute directement le fichier du venv.

⚠️
Pourquoi pas python -m addok ? Ça semble logique, mais ça ne fonctionne jamais avec addok : le paquet n'a pas de fichier __main__.py, donc Python répond 'addok' is a package and cannot be directly executed, même quand addok est parfaitement installé. La seule commande qui fonctionne est l'exécutable addok.exe lui-même.

✅ Complément : désactivez Anaconda pour un terminal propre

conda deactivate
.\venv\Scripts\Activate.ps1

Votre prompt doit ensuite afficher uniquement (venv) PS ..., sans (base). Ce n'est pas obligatoire si vous utilisez le chemin complet vers addok.exe, mais ça évite bien d'autres confusions.

ℹ️
Le script index.py ci-dessus est déjà corrigé pour appeler venv\Scripts\addok.exe directement — c'est ce qui évite le problème dès le départ.

Si pip show addok ne trouve rien dans le venv :

C'est le même conflit, côté pip cette fois : pip install addok a pu s'exécuter avec le pip d'Anaconda. Vérifiez et réinstallez en forçant le pip du venv :

# Vérifier
.\venv\Scripts\python.exe -m pip show addok

# Réinstaller si absent
.\venv\Scripts\python.exe -m pip install --trusted-host pypi.org --trusted-host files.pythonhosted.org addok

⚙️ Comprendre l'Indexation

Pourquoi filter_ndjson.py ?

Le fichier adresses-addok-france.ndjson.gz contient ~27 millions d'adresses, mais :

  • ⚠️ Certaines lignes sont corrompues
  • ⚠️ Certaines manquent des champs obligatoires
  • ⚠️ Certaines ne sont pas du JSON valide

filter_ndjson.py :

  • ✅ Vérifie que chaque ligne est du JSON valide
  • ✅ Filtre les adresses sans "name" (champ obligatoire)
  • ✅ Laisse passer seulement les bonnes données

Pipeline d'Indexation

gzip -cd fichier.gz → filter_ndjson.py → addok batch
    ↓                     ↓                    ↓
Décompresse        Filtre les bonnes    Indexe dans Redis
    données          adresses            (~27M)

📊 Géocoder vos Fichiers

📓
Le moyen le plus simple pour géocoder en masse : ouvrez le fichier notebook .ipynb fourni avec le projet. Il utilise déjà chunkcsv.py et est prêt à l'emploi dès que le serveur Addok tourne sur http://localhost:7878.

Préparation du fichier CSV

Format attendu (séparateur ;) :

adresse;code_postal;commune

Script de Géocodage

Utilisez chunkcsv.py :

    'columns': ['adresse', 'code_postal', 'commune']

    filepath_in='mes_adresses.csv',

    filepath_out='mes_adresses_geocodees.csv'
)

Résultat : CSV avec colonnes lon/lat/score ajoutées

🛠️ Dépannage

❌ "Fatal error in launcher: Unable to create process using '...\ancien\chemin\venv\Scripts\python.exe' ..."

Cause : Votre venv a été copié depuis un autre dossier. Sous Windows, les exécutables d'un venv (pip.exe, addok.exe...) contiennent en dur le chemin absolu d'origine — un venv copié est un venv cassé.

Solution : Supprimez le venv copié et recréez-le sur place : Remove-Item -Recurse -Force .\venv puis python -m venv venv et réinstallez les paquets. Voir la section "Réparez-le maintenant" dans l'installation Windows.

❌ "ModuleNotFoundError: No module named 'addok'" (avec la commande addok seule)

Cause : Prompt (venv) (base) PS ... — Anaconda et venv sont actifs en même temps, et la commande addok pointe vers l'exécutable d'Anaconda plutôt que celui du venv.

Solution : Appelez toujours .\venv\Scripts\addok.exe batch / serve par son chemin complet, au lieu de addok batch / serve ou de python -m addok (qui ne fonctionne jamais, addok n'a pas de __main__.py).

❌ "...\venv\Scripts\python.exe: No module named addok" (avec python -m addok)

Cause : addok n'est pas installé dans le venv — le pip install addok initial a probablement été exécuté avec le pip d'Anaconda au lieu de celui du venv, donc addok a été installé dans (base), pas dans venv.

Solution : Vérifiez avec .\venv\Scripts\python.exe -m pip show addok, puis réinstallez en forçant le venv : .\venv\Scripts\python.exe -m pip install addok — voir la section "Erreur fréquente" dans l'installation Windows pour le détail.

❌ "No module named addok.__main__; 'addok' is a package and cannot be directly executed"

Cause : Vous avez utilisé python -m addok .... Le paquet addok n'a pas de fichier __main__.py, donc -m addok échoue toujours, même quand addok est parfaitement installé dans le venv.

Solution : N'utilisez jamais -m addok. Appelez l'exécutable directement : .\venv\Scripts\addok.exe batch ou .\venv\Scripts\addok.exe serve. Dans index.py, utilisez os.path.join(os.path.dirname(sys.executable), "addok.exe").

❌ "SSL: CERTIFICATE_VERIFY_FAILED" sur une commande pip

Cause : Les certificats Zscaler bloquent la connexion HTTPS normale de pip. Ça arrive sur n'importe quelle commande pip, pas seulement l'installation d'addok — par exemple pip install --upgrade pip oublié sans les bons flags.

Solution : Ajoutez toujours --trusted-host pypi.org --trusted-host files.pythonhosted.org à la fin de la commande pip concernée, puis relancez-la.

Cause : Script incompatible avec cette version d'Addok

Solution : Utilisez la commande simple avec filter_ndjson.py (voir ci-haut)

❌ "ValueError: cannot find context for 'fork'"

Cause : Windows n'a pas fork() - problème multiprocessing

Solution : Utilisez Ubuntu/WSL à la place

❌ "ModuleNotFoundError: No module named 'readline'" (avec traceback, addok plante)

Cause : Le module readline n'existe pas sur Windows (Mac/Linux uniquement), et addok en a besoin dès le chargement de sa configuration. Sur Windows, ce n'est pas une erreur cosmétique : addok batch et addok serve plantent complètement sans compatibilité.

Solution : .\venv\Scripts\python.exe -m pip install --trusted-host pypi.org --trusted-host files.pythonhosted.org pyreadline3, puis relancez la commande.

❌ "Connection refused" Redis

Cause : Redis n'est pas en cours d'exécution

Solutions :

  • Windows : Ouvrez Services (services.msc) et démarrez Redis
  • Ubuntu : redis-server --daemonize yes

❌ "Indexation s'arrête après 90 secondes"

Cause : Manque de mémoire

Solution : Redémarrez, fermez autres applications, relancez (reprise auto)
